# 原片诊断、预期与替代方向（v0.7.0）

用于首片检查、用户要求难以实现或调色陷入重复尝试时。它是 Agent 使用既有 inspect、render、qc 与可选 raw_qc 的 SOP，不是新增 action，也不是自动物理判废器。

## 先取得证据，再谈限制

1. **开始时内部检查**：对实际源片调用 inspect，结合可查看画面检查目标区域的清晰度、明暗信息、噪点，以及主体/背景关系。EXIF 只描述拍摄条件，不能从高 ISO、慢快门或镜头名称直接推断废片。画面中的柔化、拖影、剪影也可能正是用户要保留的效果。
2. **RAW 看不到时先诊断显影**：有修图请求授权时，在 Session 内生成标明用途的诊断/探索试片，实际打开预览；纹理、失焦或降噪判断看完整输出的 100% 区域。它可以就是首张探索版，不固定多渲染一次。仅要求诊断时，必要试渲染限于诊断所需的新文件，不开展风格探索；明确要求先讨论或不生成文件时遵从。无法查看时只报告元数据与待验证问题，不宣布已完成视觉体检。
3. **只对疑点追加验证**：高光恢复疑问可按能力使用受控重建/曝光对照，必要时对本版支持的 Nikon Bayer NEF 调用可选 raw_qc。缺少依赖不妨碍普通试片，但不能伪造统计。全图 CFA 计数不能直接定位已旋转的画面区域；无空间对应证据时不做局部硬剪切结论。
4. **保留证据范围**：记录所看图/manifest 的实际路径、目标区域、观察到的变化与仍未知的事项。初始中性图偏暗、相机嵌入预览或导出图纯白，都不能独自证明 RAW 丢失细节；raw_qc 的解码器码值统计也不证明传感器硬件饱和或局部可恢复性。两次调整无收益仅说明当前尝试未改善，不证明所有算法、其他软件或原片都已到极限。

## 分清限制来源

| 来源 | 可报告的依据 | 应采取的下一步 |
|---|---|---|
| 原片信息不足或疑似不足 | 100% 局部可见拖影/模糊，或对照后仍无目标纹理；强度和原因仍可能待验证 | 说明可改善的观感及不能承诺的真实细节恢复，不把锐化或生成式重绘称为无损找回 |
| 当前接口/资源不足 | capabilities 没有局部选区、裁切、黑白转换等所需接口；镜头资源未匹配或未标定 | 说明本工具的具体限制，给全局折中或外部软件建议；不称为原片物理上做不到 |
| 视觉方向尚未奏效 | 调色已改变颜色，但用户关心的主体突出程度仍未改善 | 提出另一个可观察方向供比较，不把代理不喜欢的构图/光线判为物理缺陷 |

原始 JPEG 某一区域若只有均匀相同的纯白值，这些像素中没有原纹理可供普通显影恢复；这不等于周围信息也丢失，更不代表对应 RAW 无信息。不要用单个 255 像素或导出 QC 代替源片区域检查。

## 只说明影响选择的限制，并同时给出出路

有证据表明限制会影响用户目标时，在继续反复调色前简短说明“观察 + 能改善什么 + 主要代价 + 优先建议”。无关键阻碍就正常推进，不固定输出缺陷清单或“物理天花板”开场白。未确认的原因使用“目前观察到 / 需要试片验证”，不要把镜头、光照或机型写成未经检查的定论。

例：已在试片观察到提亮后的噪点增加，可说“人物提亮后表情更清楚，但暗部颗粒也更明显。我建议先保留夜色、适度提亮；更在意细节时再比较亮一些的一版。”没有看过这一现象时，只能说这是待验证的取舍。

## 调色无收益时，主动提出替代方向

- 连续两次同方向试片无可见改善，暂停该方向，保留当前候选和用户已选版。给一个最有依据的建议；需要比较时再提供少量对照，不开启无限风格遍历。
- 可在已支持控制内建议更低调的轮廓、较柔反差、偏淡色彩或保留颗粒等方向；按实际 capabilities 映射。新方向与明确 Keep 冲突时，先由用户决定是否放弃该项，不暗自转向。
- 构图建议要指出画面中的具体位置及代价，如“裁去下方部分亮地面可减少分散，但也会少掉环境交代”。当前可用 crop 和 black_white 做构图/黑白试片，graduated_filter 做按位置的渐变曝光，具体边界见 [common-controls.md](common-controls.md)。这些不等于语义选区重布光。景深重建、任意画笔蒙版、生成式消除和多图合成未接入；只能说明所需外部能力，不能伪造参数或声称已执行。未授权外部编辑时只给建议。
- A/B 若实际渲染，按 dialogue.md 的完整旧快照恢复规则从相同参考版建立分支，显式控制变量，避免第二版无意继承第一版探索参数。每张有真实 output/manifest，描述差异与代价；用户选版后再更新偏好与可接受取舍。

## 用现有 Session 留下依据

在 confirmed_brief 简记已表达目标、诊断依据/待验证项、探索方向（待选择），保持文字精简并遵守 4000 字符上限；保留仍有效的 Keep、当前待办和已选版真实路径。用户反馈到来后更新假设状态；user_feedback 只存原话。不创建 physical_ceiling、diagnostic_passed 等虚构 API 字段，不修改旧 manifest 的审核状态。技术测试通过不代表用户已经喜欢结果。


### 探索会话示例

用户只说“帮我修好看点”时，可先说明“我先试让主体更突出、保留现场色彩的方向，看图后再选”。以下 init 仅保存探索状态，不把这个建议放进 Keep；路径须替换为实际项目与源片路径：

```json
{
  "action": "session",
  "operation": "init",
  "session_path": "/用户项目/session.json",
  "source": "/用户项目/input.NEF",
  "base_profile": "builtin:neutral-rec2020-rt513",
  "confirmed_brief": "用户已表达：帮我修好看点。探索方向（待选择）：主体更突出，保留现场色彩；先用 sRGB JPEG 试看，用途尚未明确。诊断：待首片及必要局部检查，不预判原片极限。",
  "keep": [],
  "change": []
}
```

完成实际绑定渲染后，若用户原话为“脸太黄了，背景暖灯别改”，再按实际 revision 更新；以下假设当前 revision=1，不是固定值。颜色要求可能受全局控制限制，应按实片说明能否兼顾，不把整图降温承诺成局部去黄：

```json
{
  "action": "session",
  "operation": "record_feedback",
  "session_path": "/用户项目/session.json",
  "expected_revision": 1,
  "user_feedback": "脸太黄了，背景暖灯别改",
  "confirmed_brief": "用户已表达：脸部减少偏黄，背景暖灯保持。探索方向（待验证）：用全局颜色控制尝试改善肤色，不承诺局部校色；若改变暖灯则先展示取舍。诊断依据、用途与其他偏好仍待明确；sRGB JPEG 仅为试看假设。",
  "keep": ["背景暖灯"],
  "change": ["减少脸部偏黄"]
}
```

这是新建示例的完整摘要。已有会话更新时还要合并仍有效的旧要求、实际诊断证据与选版路径，不能用示例覆盖它们。工具只保存文本；假设是否误写成要求、是否满足 Keep 仍需 Agent 实际看图与用户反馈核对。
